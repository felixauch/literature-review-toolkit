# Technical documentation

The toolkit was developed with assistance from GPT-6 Astra. This guide and the accompanying documentation were generated by GPT-6 Astra.

## Modules and configuration

`toolkit.py`, `toolkit/ui/` and the generic stage scripts provide database-file import, screening, PDF management and optional citation chasing. `toolkit/review_workspace/` provides independent multi-label classification, domains, evidence fields and interactive synthesis. `workflow.py` is the common launcher; `handoff.py` connects the two modules with checked IDs and local PDF paths.

The search module reads `projects/<slug>/project.json`. It contains source exports, screening regexes, an ordered rule list, paths and optional single-label report settings. The combined workspace reads a separate configuration, conventionally `review_settings.json`: categories, domains, field groups and types, choices, required flags, interpretation flags, context rules, reading priorities and domain notes. Each prepared run holds a settings snapshot. An empty template is not a scientifically defined eligibility scheme: the reviewer must configure it.

## Import and source handling

Supported inputs are BibTeX, IEEE-style CSV and generic CSV with an explicit column map. The built-in BibTeX parser is lightweight; inspect import counts and representative records. RIS and automatic subscription-database querying are not implemented. The search log template records the query/date/filters separately from exported records.

Deduplication merges normalised DOI matches, normalised title/year matches, compatible long title prefixes in the same year and explicitly supplied DOI pairs. These rules can merge different records or miss version pairs. Inspect the logs before screening. Re-merging with `--force` is not an incremental update and can replace IDs/decisions; prepare a separate update project instead. Re-screening is intended to revise undecided suggestions while preserving saved decisions.

PDF collection supports Zotero filename/first-page matching, download-folder matching, ID-prefixed folder rescanning, exact ID-to-file CSV import and optional OA download. Source imports copy files. The earlier interface moves working copies after full-text Include and removes the project copy after Exclude. Original source files remain separate. Matching and first-page verification are heuristics; a scan can require manual reading. OCR is not included.

## Handoff and persistence

Handoff requires human title/abstract Include and full-text Include decisions and an existing local PDF for each transferred record. Unknown/duplicate IDs and missing or out-of-root sources stop preparation, rather than silently dropping records. Pending full-text records are counted in the handoff report and are not transferred as included. Original screening decisions are never modified. A timestamped input CSV and source hashes make the transfer traceable. The new run starts with unconfirmed category, domain and extraction decisions.

The search module stores decisions in CSV; JSON files hold settings, provider caches and derived browser data. The combined interface uses CSV files for decisions, extracted text, proposals and revision histories. Project settings and migration/handoff reports can remain JSON; APIs exchange JSON in memory. No database server or SQLite file is used during review. Back up the whole project and run, not just the CSV. Browser local storage is not a complete backup. Source hashes and revision checks detect changed sources and conflicting edits. Existing run folders cannot be overwritten during preparation.

## Local processing and network

There is no model SDK, model connector, local inference engine or generative-AI request in this package. Models are not downloaded or trained by the standard workflow. An optional TF-IDF/linear-SVM title-screening backcheck is a conventional classifier, uses local decisions, and has separate dependencies; it is not part of multi-label classification or evidence extraction.

Local PDF extraction uses pypdf/pypdfium2. The combined review server binds to loopback, requires a per-server write token, and blocks outbound connections and child processes after startup. Browser scripts call their local server. Search-stage network functions are explicitly separate: Crossref/OpenAlex bibliographic metadata, Unpaywall OA locations, PDF-host downloads and clicked DOI pages. They do not send PDF text to a model. Installing requirements contacts Python package repositories.

OpenAlex requests can use `OPENALEX_API_KEY` from the launching process environment. The key is placed in an Authorization header only for HTTPS requests to api.openalex.org, not in project files, URLs or log output. No key is bundled. Basic keyless queries remain supported; provider limits and availability can change. The citation cursor uses pages of at most 100 records. Unpaywall requires the reviewer's contact email. Live network services are not guaranteed by the offline regression test.

## Optional earlier reports

The source pipeline includes optional single-label charting, audit and exports for compatibility with its generic workflow. They do not replace the independent multi-label workspace. Their outputs are deliberately labelled optional in the setup page. The obsolete bulk auto-finalization and automatic human-review marking scripts are not included. Title/abstract decisions are entered one record at a time; the bulk suggestion-acceptance control and its handler have been removed. Saving or exporting several existing decisions does not accept new suggestions.

## Release checks

Optional test dependencies are listed in `requirements-test.txt`; ReportLab is used only to generate fictional PDFs in two integration tests. It is not required to run the review toolkit. After installing that file, run `python -m unittest test_setup test_configurable test_paper_sections test_reading_choices test_confirmed_exports test_csv_storage` from `toolkit/review_workspace/`.

The package manifest records every packaged file and checksum. Release checks use fictional records and PDFs, verify export parsing/deduplication, decision persistence, PDF copying, full-text steps, handoff guards and the combined interface. Runtime dependency and endpoint scans check for model clients/calls. These are software checks, not estimates of classification accuracy or a legal certification for sources.

## Browser setup

`workflow.py` opens the local setup service in the default browser. `toolkit/review_workspace/setup_server.py` serves only loopback requests, checks Host/Origin and a per-process token, validates the configuration and local source paths, and starts preparation as a background job. `setup_ui/` contains the browser forms and local path picker. No shell strings or model services are used. The search project launcher and included-paper handoff are available from this page. Existing runs and settings files are not overwritten.

Search/screening and combined review settings have different schemas. CSV column maps are editable in the older HTML setup page and preserved on save. Citation imports require an exported reviewer decision file. Unsubmitted setup fields are not persisted; Download settings saves a reusable configuration.

## Launcher and shared appearance update

The launcher validates Python 3.10+ and required imports before opening the default browser. `bootstrap_env.py` rebuilds a broken local virtual environment after moving it to a timestamped backup; it leaves project files intact. `toolkit/ui/theme.css` is shared by setup, search screening, full-text audit, classification and synthesis, and is embedded in new standalone citation-review exports. The guide screenshots were all recaptured from this release using fictional demonstration papers.

## Classification export boundary

The combined interface is the only route to a confirmed classification export. It requires every record to have current, confirmed category and domain decisions; a draft, clarification flag, changed source or missing included PDF blocks the whole export. `confirmed-corpus.csv` contains the confirmed included records and records their classification status, reviewer and confirmation time. Excluded decisions remain in the classification history/snapshot. The imported decision-link field is retained metadata; category confirmation does not confirm extraction fields.

`unfinished-classifications.csv` lists record IDs, titles, review status and the reason each record needs attention. It does not convert suggestions into decisions. The earlier report script and screening-page download instead produce `screening_corpus_draft.csv`, explicitly marked `classification_status=unconfirmed`; the report is `screening_overview_draft.md`. Related earlier report tools use this draft file, and the optional LaTeX listing is also marked draft. They neither read nor overwrite historical `final_corpus_included.csv` files. To resume an older project, rebuild its draft overview when needed. For final labels, use the combined review and export from there.

## CSV storage and standalone browser

`csv_storage.py` uses a checksummed CSV revision journal as the commit point. Atomic replacement, local file locks, expected revisions and a previous-file backup protect saves. Current-state CSVs are derived and rebuildable. `migrate_legacy.py` is the only SQLite reader: it opens old files read-only and writes a new sibling run, leaving source files intact. Failed conversions are not exposed as completed runs.

`assessment_browser.py` embeds the actual combined interface HTML, styles and JavaScript with a read-only CSV adapter. There is no separate chart implementation. Summary exports contain saved labels, field values/states and page references; they do not contain PDF text or full review history. The portable page blocks network requests and has no write API. `Load CSV` accepts a compatible summary export; use a new toolkit export if the project schema changes.

The archive endpoint locks each review journal while copying CSV/settings files. It is a consistent run-record backup, not a package of externally linked PDFs. Work in a local folder: local locks do not coordinate simultaneous edits across cloud-synchronised computers.
